# 发票合并系统

面向多店铺 Amazon FBA 发货工作的 Windows 桌面程序，用于汇总物流询价、合并货代商业发票、查看发货和物流轨迹，以及批量修改渠道、检查敏感词。

当前代码版本为 **v1.1.24**。业务数据、模板和公共配置主要放在公司 OneDrive，程序代码由 Git 管理。

请使用 `发票合并系统_V1.1.24.exe`，本版新增皓鹏货件核对：读取官方成品.xls、粘贴HPT跨行原文、同票重复FBA去重，并采用整票最低21kg。独立核对页及重测重点标记、迈创部分FBA关联、报关修改、渠道规则和原发票合并方式保留；沿用V1.1.21的启动依赖修复。

迈创报数只列部分FBA时，所列FBA须全部唯一对应一份发票，重量仍按该票全部货箱核算，并显示关联方式与未列FBA。该行为自V1.1.22提供；V1.1.21仍使用原完整集合匹配。验证与交付状态见[V1.1.22发布记录](docs/releases/V1.1.22.md)。

自V1.1.23起，货件数据核对为侧栏独立模块，位于发票中心与发票报关修改之间。结果表增加列分隔实线，“需申请重测”显示红底白字加粗标签，并突出超限差额。旧V1.1.22仍为原第5块布局；本次验证及交付状态见[V1.1.23发布记录](docs/releases/V1.1.23.md)。

## 主要功能

- **询价中心**：按国家站点、日期范围扫描询价明细，按仓库汇总重量和箱数，导出询价表。
- **发票中心**：选择货代和国家扫描源发票，核验仓库国家，在单一国家内按货代、模板版本、仓库合并，生成快越达 `.xls` 或迈创 `.xlsx` 上传文件。使用前请按[国家目录配置](docs/发票国家分流配置.md)整理源发票。
- **货件数据核对（V1.1.20 新增）**：自V1.1.23为侧栏独立模块，接收本次合并结果或手选目录，粘贴迈创或皓鹏报数后核对整票重量，支持重测筛选和Excel导出。完整集合优先，允许唯一部分FBA辅助关联；单边尺寸公差2cm、体积重系数6000、整票向上进位1kg。皓鹏自V1.1.24支持外部官方成品.xls，整票最低21kg，旧发票合并器支持范围不变。详见[操作说明书](docs/发票合并系统应用说明书.md#货件数据核对)。
- **发票报关修改（V1.1.20 新增）**：按美国/欧洲/英国/加拿大替换规则扫描迈创、快越达、皓鹏现成发票，预览四项产品字段，人工选择后另存整批；原件和原文件名保留，修改记录外置。规则表格式及操作见[操作说明书](docs/发票合并系统应用说明书.md#发票报关修改)。皓鹏仍不属于旧发票中心的合并适配器。
- **发货追踪**：读取装箱明细中的发货规划，显示 FBA、SKU、数量、货代、渠道和 Tracking，按需查询物流详情。
- **重点追踪**：保存店铺与品名条件，集中查看最近 60 天的重点产品运输情况。
- **批量修改与敏感词检查**：修改选中单元格、检查品名和材质，并提供命中定位和结果导出。
- **渠道规则模式（V1.1.20 新增）**：在批量修改页同步各账号官方服务目录，读取人工维护的渠道规则，按物流商、国家、仓库、内部渠道、包税/递延和卡派/快递派逐份生成建议，确认后另存整批。使用方法见[操作说明书](docs/发票合并系统应用说明书.md#渠道规则模式)。
- **维护**：打开中央物流地址库。发票中心还可打开货代登录网页，由操作人员自行登录、上传和下单。

## 运行

需要 Windows、Python 和 Microsoft Excel。当前项目虚拟环境为 Python **3.11.4**。

在项目根目录使用已有环境启动：

```powershell
& .\.venv\Scripts\python.exe main.py
```

首次建立环境时：

```powershell
py -3.11 -m venv .venv
& .\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

还需要本机能访问代码中配置的 `I:\OneDrive\OneDrive - Lion` 业务目录，以及中央模板、地址库和公共配置。安装 Python 依赖不会自动创建这些业务文件。

## 验证与打包

运行现有测试：

```powershell
& .\.venv\Scripts\python.exe -m pytest -q
```

测试集包含依赖真实模板、装箱明细及 Excel 自动化的用例；不属于完全独立于业务环境的测试集。`pytest.ini` 的临时目录也固定在 `D:/InvoiceMergeSystem/temp/pytest`。

2026-10-20 的 V1.1.19 发布回归：**217 passed，1 warning**（22.17 秒），包含 Excel COM 用例。接手时受限环境曾因 Excel COM 激活返回 `0x80070005` 失败，完整历史及环境差异见[交接记录](docs/项目理解与维护交接.md)。真实货代导入与 Windows 显示缩放仍需实际工作环境验收。

已有打包配置，可在具备 PyInstaller 的 Windows 环境中执行：

```powershell
& .\.venv\Scripts\python.exe -m PyInstaller --noconfirm InvoiceMergeSystem.spec
```

PyInstaller 未列入 `requirements.txt`；本机现有环境已安装。spec 在分析依赖前将构建 PATH 限定为当前 Python 和 Windows 系统目录，包自身 DLL 由 hook 收集，防止宿主工具的同名 ICU/OpenSSL 混入。当前产物位于 `dist/发票合并系统_V1.1.24.exe`，完整包位于 `release/发票合并系统_V1.1.24.zip`。发布前必须实际运行此 exe 并进入主界面，不能仅凭源码界面检查或构建成功判定可启动。验证结果及交付状态见[发布记录](docs/releases/V1.1.24.md)。

正式发版复制到公司 OneDrive 的版本目录：

```text
I:\OneDrive\OneDrive - Lion\【采购仓储】\【发货单】\【发票合并】\发票系统\发票合并系统_V<版本号>\
```

沿用历史发布位置，新建版本目录，复制已验证的 `release/发票合并系统_V<版本号>/` 内容，再逐文件比对 SHA256。V1.1.24 已于2026-11-19复制并验证全部9个交付文件，[GitHub Release](https://github.com/mylife20250103-cell/FHZZ/releases/tag/v1.1.24) 已正式发布并设为最新版本，3个附件大小和SHA256均校验通过。最终exe已实际启动，OneDrive副本与其字节一致；完整原生页面交互及皓鹏真实已填实票尚未验收，验证范围见发布记录。旧版本目录、标签和附件保留。Git 推送、GitHub Release 和 OneDrive 文件发布是三个独立步骤；云端同步状态由 OneDrive 客户端负责。
