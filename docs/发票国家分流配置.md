# 发票中心国家分流配置

本功能自 V1.1.19 提供。V1.1.18 及更早安装文件不包含本次改动。

## 生成发票时的目录

上游 Excel/VBA 根据目标仓库国家，把源发票生成到对应货代的国家目录：

```text
物流商发票/
├─ 快越达发票/未合并/
│  ├─ 美国发票/<原有下级目录及源发票>
│  └─ 加拿大发票/<原有下级目录及源发票>
└─ 迈创发票/未合并/
   ├─ 美国发票/<原有下级目录及源发票>
   └─ 加拿大发票/<原有下级目录及源发票>
```

程序负责读取这些目录，不会移动旧源发票，也不会修改或运行上游导出宏。旧文件需要按国家生成或整理后再使用默认扫描；临时追加目录可以扫描其他位置，但同样校验所选国家和物流商。

## 扫描源配置

中央配置为 `发票系统/公共配置/invoice_sources.ini`，支持两种方式。

**沿用现有配置（推荐）**：`Path` 保留在该货代的“未合并”根目录，不填 `CountryCode`。程序根据国家选择自动追加“美国发票”或“加拿大发票”，不需要改写现有中央配置。

```ini
[Source.Mayn_KYD]
Enabled=TRUE
Path=I:\OneDrive\OneDrive - Lion\【采购仓储】\【发货单】\【发票合并】\物流商发票\快越达发票\未合并
Owner=Mayn
StoreCode=美10
CarrierCode=KYD
```

**分别配置国家目录**：每个国家一条注册源，`CountryCode` 为 `US` 或 `CA`，`Path` 直接指向国家目录，不再追加子目录。

```ini
[Source.Mayn_KYD_US]
Enabled=TRUE
Path=I:\OneDrive\OneDrive - Lion\【采购仓储】\【发货单】\【发票合并】\物流商发票\快越达发票\未合并\美国发票
Owner=Mayn
StoreCode=美10
CarrierCode=KYD
CountryCode=US

[Source.Mayn_KYD_CA]
Enabled=TRUE
Path=I:\OneDrive\OneDrive - Lion\【采购仓储】\【发货单】\【发票合并】\物流商发票\快越达发票\未合并\加拿大发票
Owner=Mayn
StoreCode=美10
CarrierCode=KYD
CountryCode=CA
```

迈创同理，使用 `CarrierCode=MC` 及“迈创发票”的目录。改用分别配置时，应停用该货代原来的根目录条目，避免出现重复扫描源。`StoreCode` 不决定发票目的国家。

## 操作与校验

1. 发票中心选择国家、物流商和日期范围，核对页面显示的实际扫描路径。
2. 开始原始扫描，或扫描临时追加目录，再按原有七阶段完成合并。
3. 最终上传文件仍在 `发票系统/合并结果/<当天日期>/<批次号>/`，不会写回“未合并”。

国家依据 `_SystemMeta.WarehouseCode` 和中央 `各物流地址库.xlsx` 对应货代地址表的“国家*”列。YOW3 为 CA，LGB8、MQJ1 为 US。无需修改源发票的元数据结构，也不改官方模板原件。

错国、错货代、仓库国家缺失或冲突都会阻止扫描通过。程序不会自动把未知仓库归为美国，也不会静默跳过放错目录的发票。一次批次只允许同一货代、同一国家，国家同时记录到快照和合并计划；实际合并再次核对输入国家、箱身份及 SHA256。

活动批次按“日期＋物流商＋国家”独立恢复和复用。完成批次只清理同日同货代同国家的旧完成结果，保留其他国家、货代的结果。原有同范围旧结果替换行为仍存在，不代表长期留档。

旧快照没有国家字段时，按仓库地址解析；混国、缺地址等无法确定的旧活动批次不自动恢复或删除，需要重新扫描。旧合并计划没有国家信息时，也需重新原始扫描，不直接继续内容合并。

KYD 加拿大邮编按文本写入，例如 `K2J 7C7`；继续保留 `.xls` 二进制结构和浮动图。发布前仍需在实际桌面和货代后台验证美国、加拿大文件的导入。
