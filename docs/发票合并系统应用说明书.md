# 发票合并系统 V1.1 应用说明书

面向新同事培训。按本说明操作即可完成日常询价、合并发票、改渠道和敏感词检查。

## 1. 使用前准备

- 电脑为 Windows，已安装 **Microsoft Excel**。
- 已登录公司 OneDrive，并能打开：
  `I:\OneDrive\OneDrive - Lion\【采购仓储】\【发货单】\【发票合并】\发票系统`
- 双击 `发票合并系统_V1.1.23.exe` 启动。左侧应显示版本 **v1.1.23**，在“发票中心”和“发票报关修改”之间进入独立“货件数据核对”。部分FBA辅助关联、启动修复、报关修改和渠道规则模式均保留。
- 不要用 Excel 打开快越达刚合并好的 `.xls` 再保存，否则上传会失败。

## 2. 整体流程（先记住这一条）

询价中心 → 发票中心（扫描到内容合并，再打开货代后台登录下单）→ 如需改渠道再进「批量修改单元格值」→ 需要时做敏感词检查。  
查看 FBA / Tracking 进「发货追踪」。盯某店某个产品（例如美8 盖片）进「重点追踪」。新增仓库地址时，进「维护」打开「各物流地址库」，不要改官方发票模板。

合并完成后再改渠道。改「全部发票汇总」里的源发票，**不会**改到「合并结果」里已经生成的文件。

## 3. 询价中心

用途：扫描询价明细，生成物流询价汇总表。

日常：

1. 先选 **国家站点**（美国、加拿大，以及以后的英国、德国）。一次只导出一个国家。
2. 「从 / 到」默认都是今天。要把昨天和今天合成一单，把「从」改成昨天。页面上的 **输出 DateID** 始终是今天，汇总表也写到今天。
3. 可点 **询价路径** 打开目录核对文件：只选一天时打开当天文件夹，跨天时打开「询价路径」根目录。
4. 点 **扫描询价明细**。其他国家的文件会被跳过，不会和所选国家加在一起。
5. 检查表格无误后，按页面提示生成询价汇总。文件名带国家，例如 `20261009_美国_询价汇总_15箱.xlsx`。同一国家当天再生成会替换上一份，已填写的报价不会保留。

补扫其它目录（漏扫、补文件、不在日期文件夹里的路径）：

1. 点 **＋ 临时追加目录**，选要补的文件夹（对话框默认打开「询价路径」）。
2. 点 **扫描临时追加目录**。这条只会扫你刚选的目录，不会把当天默认目录混进来。

## 4. 发票中心

本节国家分流操作适用于 V1.1.19；V1.1.18 及更早 exe 不包含此功能。目录和配置详见[发票国家分流配置](发票国家分流配置.md)。浅色界面保留原有业务操作；较矮窗口可在发票中心和询价中心向下滚动查看按钮。

用途：按批次把物流商发票合并成可上传文件。步骤条为：

① 原始扫描 → ② 快速合并 → ③ 二次扫描 → ④ MergePlan → ⑤ 内容合并 → ⑥ 结果检查 → ⑦ 完成

日常：

1. 「从 / 到」选扫描范围，默认今天。跨天时把「从」改成昨天。批次号和合并结果目录始终写到今天。
2. 选择 **国家** 和 **物流商**，确认扫描路径为该货代“未合并”下的“美国发票”或“加拿大发票”。点 **开始原始扫描**，只读取所选目录及日期范围。
3. 按页面主按钮往下走。准备合并会连续做 ②③④；确认后再点 **开始内容合并**。
4. 合并结果在：
   `发票系统\合并结果\日期\批次号\`
   - 快越达：`KYD_仓库_箱数箱.xls`（同一仓库合成一份，例如 `KYD_PSP3_10箱.xls`）
   - 迈创：`MC_仓库_箱数箱.xlsx`

5. 合并完成后，在本页 **4 货代下单** 选货代和下单账号，点 **打开下单后台**。会用系统默认浏览器打开该货代登录页。请自己登录并上传「合并结果」里的文件。程序不会自动登录，也不会自动下单。迈创多家账号共用同一网站，打开后请登录刚才选的那个账号。

补扫其它目录：

1. 点 **＋ 临时追加目录**（默认打开「物流商发票」）。
2. 确认国家和物流商后，点 **扫描临时追加目录**。临时目录同样校验国家与货代，不能混入另一国家的发票。

注意：

- 源发票应在生成时按国家分目录；程序发现误放或国家未知会报错，不会自动移动文件。
- 切换国家或物流商会恢复对应的未完成批次。完成一国批次不会清理其他国家或其他货代的结果；同日同货代同国家的新完成批次仍会清理该范围旧结果。
- 旧计划提示缺少国家信息时，请重新原始扫描后再合并。
- 快越达合并结果必须是 `.xls`。不要用 Excel 打开后保存。
- 迈创合并结果是 `.xlsx`，B2 渠道用模板自带名称。
- 内容合并失败时，弹窗可点 **打开自检报告**，按文件看缺字段、海关编码、图片网址等问题。

## 4.1 发票报关修改（V1.1.20 新增）

使用 V1.1.21，可在左侧“发票中心”下方看到“发票报关修改”。功能自 V1.1.20 新增，V1.1.19 及更早 exe 不包含此功能。

1. **准备规则**：在 `发票系统\报关信息替换` 放一份 `.xlsx`，也可选择其他路径。第1行左侧“修改前”、右侧“修改后”；第2行为字段名，第3行起每行一条规则。修改前含“店铺名称、产品中文品名、产品英文品名、产品材质、产品海关编码”，修改后含这四项产品字段，顺序可调整，允许额外产品名称列和空白分隔列。材质可写“产品材质”或“英文材质”，编码可写“产品海关编码”或“HS CODE”；同时列出中英文材质时，统一取英文材质，中文材质不写入发票。分组标题可以合并单元格；修改后全空的产品视为未启用规则，自动跳过，已开始填写的规则必须补齐四项，不接受公式。海关编码建议先把Excel列设为文本，以保留前导零。
2. **选择范围**：选择一家货代的一批已合并发票目录及规则区域。物流商默认“自动识别（按模板）”，修改批次路径时也会重置为自动识别，以免沿用上一批货代；可手动指定货代。自动识别核对真实文件格式、工作表及表头，并在预览状态显示识别结果；混合货代目录或不明模板不能处理。发票中心成功内容合并后会自动传入路径及已知货代；皓鹏需选择外部生成的现成发票。快越达使用`.xls`，迈创使用`.xlsx`，请选择正确货代，不能直接改文件后缀。美/欧/英/加店铺前缀分别匹配美国/欧洲/英国/加拿大，同一区域跨店共用规则。区域选择用于筛规则，请自行核对发票实际目的国。
3. **扫描预览**：默认最低相似度95%，可以调整。精确匹配优先；不同替换方案同时命中时，先选择候选。原中文/英文品名、材质、海关编码与对应新值并排展示，表格可向右滚动。原中文品名必需，其他原值可空；不覆盖原公式。扫描时不会修改文件。
4. **人工确认**：逐行勾选，或点“勾选已确定方案”，检查后点“确认修改并另存整批”。未选候选和未勾选行保持原内容。规则、阈值、区域或路径更改后需要重新扫描；扫描后文件清单/内容或规则变化，也会阻止执行。
5. **使用结果**：默认保存至 `发票系统\报关修改后目录\日期\货代\批次_原目录名\修订_唯一编号\`。只上传其中“上传发票”子目录的文件；原文件名和相对子目录保留，未命中文件原样复制。“修改记录”另存JSON审计及发生修改文件的原始快照，不在发票内加工作表。

遇到失败，不会发布成功修订目录，也不会回写原发票；以“.进行中_”开头的目录不能上传。关闭已打开的发票后重试，必要时重新扫描。目标字段错误值、公式、源发票元数据、未知模板和快越达Excel另存标记会拦截。

迈创使用局部XML替换，快越达/皓鹏使用二进制流局部修改，以保留模板结构、渠道、图片、公式和下拉。结构检查通过仍需货代后台实际导入验收；皓鹏尤其需要已填写且成功导入的样本，当前模板不能证明所有真实明细格式均兼容。

## 4.2 货件数据核对

当前源码已将货件核对移为独立页面：左侧“发票中心”→“货件数据核对”→“发票报关修改”。点击“货件数据核对”进入，发票中心不再包含原第5块。切换页面保留目录、报数及结果，核对任务进行中仍有关闭保护；发票顶部七阶段保持原含义。

独立页面和重点标记自V1.1.23提供。旧V1.1.22 exe仍位于发票中心“4 货代下单”下方的“5 货件数据核对”，请使用新版本。

自V1.1.22支持部分FBA辅助关联；旧V1.1.21 exe仍要求完整集合匹配，请使用本版程序。

1. 内容合并成功后，独立核对页面自动带入并读取本次结果目录（不强制跳转页面）。也可点“选择历史目录”后“读取合并结果”；程序启动时优先建议当天最近成功合并的目录，没有记录时建议当天结果根目录。
2. 每份 MC `.xlsx`、KYD `.xls` 或皓鹏官方成品 `.xls` 作为一票，按完整箱号去重。迈创读取模板页第18行起A/C/D/E/F列，快越达第30行起A/O/P/Q/R列。皓鹏读取“单票下单-填写表”第19行起A/G/H/I/J列，B1渠道、B2完整仓库编码、B14箱数，按真实专用表识别，支持非标准文件名。箱号、重量/尺寸、表头、仓库或箱数异常会显示“源数据异常”；皓鹏量尺错误但可读的箱身份仍参与跨文件冲突检查。
3. 迈创报数统一为 `MC单号(FBA列表) 渠道 整票最终计费重量kg`，一票一行，多个FBA用逗号分隔。完整列表优先；迈创只列部分FBA（例如前3个）时，所列号码必须全部唯一对应同一份同货代发票，才辅助关联。重量始终覆盖该发票全部货箱，不能只计算文字列出的箱。支持中文/英文括号及分隔符、大小写kg和行尾反斜杠；结尾通知单独忽略。快越达仍只提供结果读取/预估，未新增其部分报数协议。
4. 核准上限＝MAX（整票实重合计，逐箱 `(长+2)×(宽+2)×(高+2)/6000` 合计），最后整票向上取整到1kg。皓鹏单独采用整票最低21kg，最终上限再与21kg取大，MC/KYD原口径不变。长宽高用cm，重量用kg；不额外增加实重公差，也不逐箱取大或逐箱进位。
5. 先找完整集合，找不到再检查迈创/皓鹏部分FBA是否全部指向唯一同货代发票。一个号码未知、跨多份文件、多候选、重复单号/跨票FBA、源文件交叠或同文件对应多条报数时，都不作重量通过判定。成功关联后，计费重高于整票上限显示“需申请重测”，等于上限允许；渠道不同另行提示。“所含FBA”和箱数为整票内容，“关联方式”“报数未列FBA”展示关联依据。
6. 结果表用实线分隔列和行。需申请重测显示红底白字加粗标签，选中行后仍保持明显；超限差额加粗突出。勾选“只看需重测”筛选，双击有源文件的结果（包括红色标记处）查看整票箱级尺寸与重量。点“导出当前结果”另存xlsx，包含当前筛选结果、关联方式、报数未列FBA、整票货箱和完整粘贴原文；原文不自动补号，可在源文件之后被重合并清理时继续留档。导出不覆盖源发票，状态文字与数值仍按原规则输出。

统一格式示例（每个MC单号一行）：

```text
MC010295347(FBA19W1YVXJ4) 美速达快提卡派 13kg
MC010295346(FBA19W1TNS6X，FBA19W1V6CBB，FBA19W12J9T1) 美速达美东卡派 50kg
```

20261104-B0001批次的MC010295346实际有4个FBA，上述3个FBA唯一指向SWF2发票，程序会辅助关联并显示未列FBA19W1GXDN9，使用全部4箱得到49kg核准上限，与整票50kg比较，超1kg需申请重测。ONT8的MC010295351按全部6箱算得75kg，上报76kg，同样超1kg。原17条报数可全部关联，其中6票部分关联。

V1.1.24新增皓鹏：手选外部生成的最终上传发票目录，读取后直接粘贴原文，可连续包含多票：

```text
HPT12247356/FBA19XC954T9/FBA19XC954T9
D14787XJY小鲸渔XK-皓鹏 加拿大海运美转加合德/以星21日达-卡派按公斤 报关方式非单证报关 收费重159.00KG
```

按HPT订单分段，票内重复FBA去重，渠道保留“按公斤”等完整内容，收费重支持小数；客户前缀及末尾确认通知不作为渠道。不同订单重复FBA仍拦截，格式错误时保留可读身份参与重复检查。单个FBA可以包含多个完整箱号，核算全部货箱。皓鹏计算值不足21kg时，报21kg允许，报21.01kg需重测；计算值21.01kg则核准上限为22kg。通知里提及地址不等于程序已核对地址，程序不向货代发送确认或重测申请。现有旧合并器不新增皓鹏输出。

更换目录或编辑报数后需重新核对。任务期间控件暂时禁用，主窗口不能关闭；有新批次到达时，结束旧任务后切到新目录并清理旧报数。若下单前另存了改渠道的副本，应手选最终用于下单的目录，避免沿用原渠道。

已核实历史样本的核准上限：GYR3 41kg、IAH3 17kg、IND9 23kg、RDU2 26kg、RMN3 17kg，KYD CLT2 54kg。用户提供的17条迈创消息与2026-11-12样本目录FBA不同，不会被强行匹配。只有总计费重量时可以筛查超限，不能定位哪箱哪条边超过2cm，需货代补充箱级尺寸/称重。

## 5. 发货追踪

用途：按店铺 / 月份（或日期范围）扫描装箱明细，查看 FBA、SKU、数量，并从货代拉取 Tracking。

日常：

1. 店铺可选某一店，或 **全部店铺**。
2. 月份选具体月份，或选 **其他** 再填日期范围。全部店铺不要选「全部月份」。
3. 点 **扫描发货规划**。
4. 用 **FBA**（或 SKU / 产品中文品名 / 运单号）筛选表格。
5. 点 **从货代拉取**，会查当前筛选结果里的全部 FBA，并填写 Tracking 和「最新物流信息」（路由里时间最新的一条）。已有 Tracking 时，点击蓝色运单号可看详情。
6. 选中一行可点 **加入重点追踪**，之后到「重点追踪」查看。

表格列顺序：候选货代后面是 SKU / 数量 / 产品中文品名，再是 FBA，方便截图给货代。

注意：

- 确认货代来自发票扫描后的 CarrierCode；没有确认时按文件名候选货代查询。
- 货代密钥在 OneDrive `发票系统\公共配置\forwarder_api.ini`，不要拷进安装包。
- 拉取 Tracking 需要能访问快越达 / 迈创 / 皓鹏 / 利合网关。

## 6. 重点追踪

用途：盯某店某个产品最近 60 天的运输情况，不必每次在发货追踪里重筛。

日常：

1. 选店铺，品名填包含关键字（例如「盖片」），可选再填 SKU，点 **加入重点**。
2. 进入本页会自动扫描最近 60 天，按店铺 → 品名 → 发货日期（从早到晚）排列。
3. 默认不显示已签收；给货代对账时勾选 **含已签收**。
4. 点 **刷新物流** 只查这些 FBA 的 Tracking。

清单保存在 OneDrive `发票系统\发货追踪\watchlist.json`，换电脑也能看到同一份重点。

## 7. 批量修改单元格值（改发货渠道）

用途：合并完成之后，批量改渠道单元格。

以下为原有“手工修改”页签的操作；此模式仍在原文件写入，与新规则模式的另存行为不同：

1. 点 **选择文件夹**，进入当天「合并结果」批次目录，例如：
   `发票系统\合并结果\20260820\20260820-B0012`
2. 表里应出现 `KYD_IND9_1箱.xls` 这种名字，而不是 `IND9_FBA..._快越达发票.xlsx`。
3. 快越达目标单元格一般是 **B4**。填写新渠道后勾选文件，点 **批量执行**。
4. 用鼠标悬停文件名可看到完整路径，确认是「合并结果」再执行。

如果勾选的是源发票（带「快越达发票.xlsx」），程序会提醒：改这些不会更新合并结果。请取消，改选 `.xls` 箱文件。

<a id="渠道规则模式"></a>

## 7.1 按渠道规则（V1.1.20 新增）

进入“批量修改单元格值”的“按渠道规则”页签。官方目录与内部规则分别保存，更新目录不会覆盖人员补充的渠道分类或仓库适用关系。

1. 点“同步官方服务目录”，核对账号数、服务数、成功时间及失败账号；可以“查看目录”或“导出服务汇总”。同名服务在不同账号下分别保留，不能跨账号套用。目录不提供完整目的仓库覆盖证明。
2. 点“创建空白规则表”，用 Excel 补充“渠道规则”工作表，每行填写：启用、物流商（MC/KYD/HP）、国家、仓库代码、内部渠道、税费方式、派送方式、账号标识、服务代码、发票填写值。账号和代码从导出的目录复制，填写值使用货代确认的准确文本。税费为“包税”或“递延”，派送为“卡派”或“快递派”。不包税按本公司内部口径归入递延，不改变官方原名。没有预填的启用业务映射，不能把样例当作已验证规则。
3. 选择并读取规则文件，再选择一个已合并批次或报关修订目录。选择修订根目录会只读取其“上传发票”；“修改记录/原件”和“.进行中_”暂存结果禁止扫描。合并成功通知会传入本次合并路径，之后仍可改选修订稿。
4. 选择本批内部渠道、税费、派送方式，生成预览。国家由发票仓库对应的中央地址库确定，不从文件名猜测。皓鹏仓库规则使用 B2 的完整地址库编码（可能含邮编后缀）。默认目标为 MC 模板!B2、KYD 模板!B4、HP 单票下单-填写表!B1；“服务单元格”可覆盖，但必须通过标签、表头和合并格检查。
5. 每份发票可单独修改内部渠道、税费、派送方式；条件变化后重新匹配。唯一规则产生建议但不自动勾选，多候选必须选定；缺项或失效服务不能直接执行。可从当前货代的账号目录“人工选服务”，也可在已有服务选择基础上编辑填写值；人工调整只影响本次，不自动写回公共规则。
6. 人工核对后勾选所需行，点“确认并另存整批”。仅修改服务格，不自动修改税号、交税方式或其他派送字段。默认根目录为“发票系统/渠道修改后目录”，可调整。每个独立修订下，“上传发票”含整批发票和原文件名，未选发票原样复制；“修改记录”含 JSON 记录及已改文件的原件。

规则、目录、地址库、源发票清单或内容在预览后变化，必须重新扫描。失败的“.进行中_”目录不能上传。目录缓存及本机默认路径位于 `%LOCALAPPDATA%/InvoiceMergeSystem/channel_catalog.json`、`channel_modify.json`，不含 Token。

新模式支持 MC、KYD、HP 发票，目录同步还可显示现有利合账号；利合发票尚未适配。原发货追踪仍读取“合并结果”的渠道，尚未接入修订稿，不能将新目录的修改视为追踪数据已更新。真实货代上传仍需验收；请使用 V1.1.21 exe。

## 8. 敏感词检查

用途：检查产品英文/中文品名、材质是否命中物流敏感词。

1. 选择要检查的文件或文件夹。
2. 点 **开始检查**。命中后可打开定位，或按规则改单元格后再导出。

写入前请先关闭 Excel 里已打开的同一文件。

## 9. 维护（各物流地址库）

用途：打开需要人工维护的中央文件，方便找到路径。

1. 左侧进 **维护**，或首页点「进入维护」。
2. 「各物流地址库」旁点 **打开文件**。路径为：
   `I:\OneDrive\OneDrive - Lion\【采购仓储】\【发货单】\发货单各源抓取\各物流地址库.xlsx`
3. 快越达改「快越达地址库」，迈创改「迈创地址库」。新增仓库只改这份表。
4. **不要**改 `发票系统\模板` 里官方模板自带的「地址库」工作表。合并时程序会按这份中央表写入。

## 10. 常见问题

**Q：批量修改显示成功，但合并结果里的 B4 没变？**  
A：多半改到了「全部发票汇总」里的源发票。请重新选择「合并结果」里的 `KYD_仓库_N箱.xls`。

**Q：快越达上传报请求错误 / 图片无法识别？**  
A：文件被 Excel 另存过。请重新内容合并，不要用 Excel 打开 `.xls` 再保存。改渠道请用本系统的批量修改。

**Q：快越达上传报「图片不能为空」，同批次其它仓库却正常？**  
A：V1.1.8 及更早在超过 8 箱时会把模板「总申报」共享公式写坏。请用 **V1.1.19** 重新内容合并，上传 `KYD_仓库_N箱.xls`（可以是 10 箱一份）。不要用 Excel 打开后保存。

**Q：内容合并失败，怎么知道是哪几张发票有问题？**  
A：失败时程序会逐张检查源发票，弹窗点 **打开自检报告**。报告在批次目录 `content_merge_diagnose.txt`，会写出箱号、缺字段、海关编码、图片网址、地址库等问题。先改源发票再重新内容合并。

**Q：迈创导入提示找不到服务？**  
A：不要把源发票里的旧渠道名写进模板 B2。V1.1 合并已保留模板自带渠道名。

**Q：其它电脑打不开业务目录？**  
A：确认该电脑已映射同一 OneDrive 路径到 `I:\`，并能打开「发票系统」文件夹。发货追踪还需要能打开「装箱明细」。本程序不把发票文件打进安装包。货代密钥在 `发票系统\公共配置\forwarder_api.ini`，换电脑不必再配。

**Q：双击 exe 报 Errno 22 / Invalid argument，路径指向 `发票合并系统_V1.1.15\logs\app.log`？**  
A：V1.1.15 会把日志写到 OneDrive 里的 exe 同目录，部分电脑写不进去就会闪退。请改用 **V1.1.19**。写不了 exe 同目录时，日志在 `%LOCALAPPDATA%\InvoiceMergeSystem\logs\app.log`。

**Q：迈创内容合并很慢，或报 Excel 共享违规？**  
A：请用 **V1.1.19**。迈创不再每个仓重开 Excel。快越达合并方式未改。同一批次仍不要两台电脑同时点「开始内容合并」。

**Q：日志在哪？**  
A：优先 exe 同目录下的 `logs\app.log`。从 OneDrive 直接打开、该目录写不了时，在 `%LOCALAPPDATA%\InvoiceMergeSystem\logs\app.log`。

**Q：合并报地址库没有某个仓库？**  
A：到「维护」打开「各物流地址库」，在对应物流商工作表补上该仓编码后再合并。不要去改官方发票模板。

**Q：点「打开下单后台」会自动登录或自动下单吗？**  
A：不会。只打开该货代的登录网页。Token 只用于发货追踪查轨迹，不会写进浏览器。迈创多家账号打开的是同一个网站，请在网页里登录所选账号。

**Q：找不到询价明细文件夹？**  
A：在询价中心确认「从 / 到」日期范围，点 **询价路径**。单天打开当天目录；跨天打开询价路径根目录。目录还不存在时，程序会提示完整路径。
