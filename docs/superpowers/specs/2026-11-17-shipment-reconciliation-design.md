# 货件数据核对设计

依据：用户已确认的第5块流程、尺寸公差/整票进位口径，以及17条迈创报数样例；本次请求授权按此方案实现。

## 目的与范围

在发票中心“4 货代下单”下方增加独立的“5 货件数据核对”，默认读取本次成功合并的目录，也支持历史目录。流程：读取合并文件→粘贴货代报数→按货代及完整FBA集合匹配→显示差额→筛选需重测→导出。顶部七阶段和发票写入流程不变，不自动下单或修改货代数据。

## 已确认规则

- 一份合并文件是一票预估。MC读取模板页第18行起A/C/D/E/F列；KYD读取第30行起A/O/P/Q/R列，核验表头及箱数。
- 完整箱号去重，再从末尾U加六位序号提取FBA。同箱多产品行不重复加重；箱重、尺寸矛盾或缺失时不可判通过。
- 原体积重＝长×宽×高/6000；公差体积重＝(长+2)×(宽+2)×(高+2)/6000，单位cm/kg。
- 仓库预估＝MAX(整票实重合计,原体积重合计)。核准上限＝MAX(整票实重合计,公差体积重合计)整票向上取整到1kg，只在最终进位一次。
- 货代报的是最终计费重量；大于上限需申请重测，等于上限允许。实重不另加公差。
- 迈创报数包含MC数字单号、括号内FBA列表、渠道和kg重量。兼容中英文逗号/括号、大小写kg、粘贴尾部反斜杠；通知文字单独忽略并显示数量。
- 仅完整FBA集合相等才匹配。重复单号、跨报数重复FBA、同货代不同源文件中的FBA交叠、重复源文件、部分交集均不可自动通过。格式异常报数也保留可识别身份参与重复检查。渠道不同明确提示，保留双方原文。
- 本次自动报数解析按迈创真实样例实现；KYD先提供文件读取及预估，不猜测其运单格式。

## 界面与结果

目录输入、选历史目录、读取按钮；报数粘贴区及核对按钮；只看需重测；导出当前结果。表格展示单号、FBA、仓库、双方渠道、箱数、实重、预估、核准上限、货代计费重、超限差额、状态、原因和源文件。双击查看箱级明细。

读取、核对、导出通过TaskWorker执行，使用finished回收线程后开放操作。更改目录/报数后作废旧结果；新合并信号在忙碌时排队，结束后切到新批次并清理旧预览。关闭主窗口时保护新任务。

导出独立xlsx，包含当前筛选结果、关联货箱明细、完整报数原文和参数/扫描时间。保留异常与未匹配行，防止漏核对；不得覆盖任何源发票。原文按文本写入，避免被Excel当成公式。

## 实现选择

采用本机只读解析和粘贴文字核对，复用现有成功信号、Qt样式和openpyxl/xlrd依赖。无需接口账号或截图识别；Excel导出供留档，程序内表格供日常操作。

## 验证

17条消息全部提取并忽略结尾通知；测试全角标点、重复、缺字段及非法重量。用合成MC/KYD工作簿验证字段、去重、冲突和实际样例的41/54/17/23/26/17kg上限；核验41允许/42需重测、部分集合不匹配、渠道冲突与导出原文安全。界面测试批次切换、预览失效、筛选/导出和忙碌关闭保护。真实发票只读抽样。
